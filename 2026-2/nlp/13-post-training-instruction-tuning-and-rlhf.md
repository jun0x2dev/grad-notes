# 13주차: 다음 단어를 맞히던 언어 모델이 지시를 따르고 사람이 선호하는 답을 내도록 추가 학습한다

지난주에는 BERT, GPT, T5 같은 트랜스포머 기반 모델의 사전 학습을 봤고, 이번 주 주제는 그 뒤에 이어지는 사후 학습(post-training)이다. 인스트럭션 파인 튜닝을 먼저 보고, RLHF(Reinforcement Learning from Human Feedback)의 목적 함수를 policy gradient로 푸는 과정과 보상 모델을 학습하는 방법까지 갔다. 2주 분량이라 뒷부분은 다음 시간에 이어서 한다.

## 언어 모델은 원래 비서가 아니다

언어 모델은 크기와 학습 데이터가 빠르게 늘어 왔다. 수업에서 든 수치로는 BERT가 약 30억 토큰, GPT-3가 약 2천억 토큰, 2022년의 Chinchilla가 1.4조 토큰을 학습했다. 사람은 13살까지 보는 텍스트가 1억 단어 이하라고 하니 훨씬 효율적으로 배우는 셈이다. 지금은 웹의 텍스트는 거의 다 봤다고 할 정도라 더 학습할 데이터가 포화됐다는 이야기가 나오고, 웹의 방대한 데이터와 사람이 쓴 고품질 데이터를 섞어서 학습한다.

다음 단어를 예측하도록만 학습한 모델이 원의 방정식을 풀고, 주석만 보고 감정 분석 웹 서비스를 호출하는 코드를 채우고, 조건에 맞는 코스 메뉴를 추천한다. 코퍼스의 패턴을 흉내 내는 것인지, 지식을 익혀 세계 모델처럼 동작하는 것인지 질문해 볼 수 있다. 여러 일을 해 주는 비서인지도 물을 수 있다.

두 번째 질문의 답은 그냥은 아니라는 것이다. GPT-3에 어떤 개념을 몇 문장으로 설명해 달라고 넣으면, 설명이 나오는 게 아니라 비슷한 요청 문장이 이어서 생성된다. 언어 모델은 말 그대로 다음 단어를 예측하는 모델이다. 사용자의 의도에 맞게 답하게 하려면 추가 학습이 필요하다. 크게 인스트럭션 튜닝과 RLHF 두 단계이고, 사전 학습 이후의 학습을 통틀어 사후 학습이라고 부른다. 예전에는 잘 쓰지 않던 말인데 지금은 업계와 연구자가 공통으로 쓰는 용어가 됐다.

## 특정 태스크 하나가 아니라 여러 태스크를 한꺼번에 파인 튜닝한다

사전 학습과 파인 튜닝은 NLP에서만 쓰는 말이 아니라 딥러닝 전반의 용어다. 많은 데이터로 먼저 학습해 일반적인 지식을 익히게 하고, 원하는 태스크에 맞춰 추가 학습한다. 언어에서는 다음 단어 예측이 사전 학습이다. 이미지에서는 1000개 클래스의 ImageNet으로 CNN을 학습하면 아래층은 에지를, 위층으로 갈수록 물체를 이해하는 특징을 뽑게 된다.

앞에서 본 파인 튜닝은 영화 리뷰의 긍정, 부정 분류용 모델 하나, 개체명 인식(NER)용 모델 하나처럼 태스크마다 모델을 따로 만들었다. 이것을 확장해서 한 모델을 여러 태스크에 동시에 적응시키는 멀티 태스크 학습을 한다. 수학, 과학, 영어처럼 서로 시너지가 나는 태스크를 함께 배우면 한쪽에서 익힌 문제 해결 능력이 다른 쪽에도 도움이 된다는 가정이다. 체육처럼 상관이 낮은 것보다는 서로 가까운 태스크일수록 그렇다. 데이터가 많아지는 효과도 있다.

### 지시와 정답의 쌍을 모은다

인스트럭션 파인 튜닝은 멀티 태스크 파인 튜닝과 개념이 같고, 데이터를 지시(instruction)와 출력의 쌍으로 구성하는 점이 특징이다. 여러 태스크의 쌍을 모은 데이터셋이 지난 시간에 T5에서 본 FLAN 데이터다. 학습한 뒤에는 학습에 쓰지 않은 새로운 태스크도 잘하는지를 본다.

지시를 넣으면 답이 나오는 것이 지금은 당연하지만, 당시에는 이렇게 지시를 그대로 밀어 넣어도 된다는 것이 새로웠다. 그동안 데이터와 모델의 규모가 성능을 끌어올려 왔으니 데이터셋도 키웠다. Super-NaturalInstructions는 번역, 질의응답, 프로그램 실행을 비롯한 아주 많은 NLP 태스크를 모은 큰 데이터셋이다.

## 모델의 지식은 MMLU 같은 벤치마크로 잰다

MMLU(Massive Multitask Language Understanding)는 2021년에 나온 벤치마크로, 수능 문제 같은 데이터셋이라고 보면 된다. 추상대수학, 해부학, 천문학 같은 57개 과목의 사지선다 문제이고, 고등학교와 대학 수준이 섞여 있다. 찍으면 25%가 나오고 거기서 얼마나 올라가는지를 본다. 새 모델이 나오면 점수를 공유하는 표준처럼 쓰인다. 평가하는 것은 지식이다. 도구를 써서 어떤 작업을 수행하는 능력을 재는 것은 아니다.

모델이 커지면서 벤치마크 점수가 포화되면 더 어려운 벤치마크가 나오고, 새로운 능력을 어떻게 평가할지에 대한 연구도 많다. 음성을 얼마나 이해하고 추론하는지를 보는 멀티모달 버전도 있다. BIG-Bench는 단순 지식이 아니라 상식, 논리적 추론 같은 태스크를 모은 벤치마크다.

### 튜닝의 효과는 모델이 클수록 커진다

T5는 인코더-디코더 구조의 트랜스포머 모델이고, 문장의 일부를 빈칸으로 만들어 채우게 하는 span corruption으로 사전 학습했다. 여기에 FLAN 데이터의 1800개 태스크를 추가 학습한 것이 FLAN-T5다. BIG-Bench와 MMLU에서 T5와 비교하면 성능이 올라가고, 모델이 클수록 그 차이도 커진다.

질의응답 문제를 예로 보면, 튜닝하지 않은 모델은 문제를 넣었을 때 답하지 않고 그 뒤에 이어질 법한 글을 생성한다. 튜닝한 뒤에는 답을 한다. 사전 학습이 일반적인 지식을 쌓는 단계라면, 인스트럭션 튜닝은 질문에 답하는 입출력 형식에 맞춰 주는 단계로 볼 수 있다. 목표는 아주 다양한 태스크를 보게 해서, 보지 않은 태스크도 어떻게 수행하는지 아는 모델을 만드는 것이다.

## 튜닝 데이터를 언어 모델로 만든다

Meta가 LLaMA를 공개하면서 인스트럭션 튜닝 데이터를 만드는 일이 빨라졌다. OpenAI 같은 앞선 회사들은 API만 제공하던 때였다. 이전에는 데이터를 사람이 모으거나 만들었는데, 이제는 잘 만든 언어 모델로 지시와 입력, 출력을 모두 합성한다.

Alpaca는 LLaMA 7B를 52,000개의 지시 수행 데이터로 추가 학습한 모델이다. 사람이 잘 작성한 시드 태스크 175개를 놓고, GPT-3 계열의 text-davinci-003에 지시 수행 샘플을 만들게 한 뒤 그 데이터로 SFT(supervised fine-tuning)를 했다. 잘 만든 모델의 API를 호출해 데이터를 뽑아 내고, 그것으로 다른 사전 학습 모델을 가르치는 증류(distillation)다. 중국 모델이 미국 모델을 어떻게 따라잡았느냐는 뉴스에 나오는 방법이 이런 것이다.

LIMA 논문은 인스트럭션 튜닝에 생각만큼 많은 데이터가 필요하지 않다고 주장했다. 좋은 샘플 1,000개만으로 학습하고 다른 모델들과 답변을 1대1로 비교해 평가했는데, 52,000개를 합성해 학습한 Alpaca 65B에도 뒤지지 않았다. 사전 학습이 잘 된 모델이라면 어떤 입력에 어떤 출력을 내야 하는지를 적은 데이터로도 가르칠 수 있다는 이야기다.

## 지시를 따르게 한 다음에는 사람이 더 좋아하는 답을 만들게 한다

인스트럭션 튜닝이 지시를 수행하게 만드는 단계라면, 그다음은 그 결과를 사람이 더 좋아할 만하게 강화 학습하는 RLHF다. 인스트럭션 튜닝만으로는 부족한 이유가 있다.

- 정답 데이터가 비싸다. LIMA처럼 적은 데이터로 된다는 결과가 있어도 잘 작성한 데이터는 필요하다.
- 열린 생성에는 정답이 하나가 아니다. MMLU는 객관식이지만 소설이나 시를 쓰는 일, 코드를 작성하는 일은 답이 여러 가지다.
- 다음 토큰 예측 손실은 모든 토큰의 오차를 평균 내서 똑같이 벌점을 준다. 판타지 TV 쇼를 홍보하는 문장에서 정답이 "판타지"여도 "어드벤처"를 넣을 수 있고, "쇼" 대신 "뮤지컬"도 틀리지 않다.

그래서 미리 만든 튜닝 데이터의 가능도를 높이는 대신, 사람이 어느 답을 더 선호하는지를 직접 받아 학습할 수 있는지를 묻게 된다.

### 목표는 보상의 기댓값을 키우는 것이다

요약 태스크를 예로 든다. 기사 하나에 모델이 만든 요약 s1과 s2가 있고, 사람이 s1에는 8.0점, s2에는 1.2점을 줬다고 하자. 이 점수가 보상(reward) R(s)다. 범위 제한이 없는 실수이고 높을수록 사람이 좋아하는 답이다. 언어 모델의 파라미터를 θ, 모델이 문장 s를 생성할 확률을 pθ(s)라고 하면, 목표는 모델에서 샘플링한 s의 보상 기댓값 E[R(s)]를 최대로 만드는 θ를 찾는 것이다.

RLHF 파이프라인은 세 단계다.

1. 인스트럭션 튜닝: 지시에 대해 사람이 작성한 답의 쌍으로 학습한다.
2. 보상 모델 학습: 하나의 프롬프트에 대해 모델이 만든 여러 답을 레이블러가 순위를 매기고, 이 순위로 답을 넣으면 점수를 내는 보상 모델을 학습한다.
3. 강화 학습: 모델이 프롬프트에 답을 생성하면 보상 모델이 점수를 매기고, 점수가 높아지도록 모델을 갱신한다. PPO 알고리즘을 쓴다.

강화 학습은 오래전부터 연구됐지만 딥러닝에 적용된 지는 오래되지 않았다. 최적화가 어려웠기 때문이다. 2016년 알파고처럼 게임에서 먼저 효과를 냈고, 언어 모델에는 잘 적용되지 않다가 제약을 완화한 PPO를 적용하면서 작동하기 시작해 많이 쓰이게 됐다. credit assignment 같은 문제도 있다.

## 보상 함수는 미분하지 않아도 된다

기댓값을 최대화하는 것이니 경사 상승(gradient ascent)을 하면 된다. 새 파라미터는 현재 파라미터에 E[R(s)]를 θ로 미분한 값을 더한 것이다. 문제는 이 미분을 어떻게 추정하느냐이고, 보상 함수는 θ로 직접 미분할 수 없다. 이때 policy gradient 방법을 쓰고, 대표적인 알고리즘이 REINFORCE다.

1. 기댓값의 정의대로 풀어 쓰면 모든 s에 대해 R(s) pθ(s)를 더한 것이다.
2. 합의 미분은 안으로 들어갈 수 있다. R(s)는 θ의 함수가 아니므로 pθ(s)만 미분하면 된다.
3. 로그 미분의 성질을 쓴다. log x를 미분하면 1/x이고 x 자리에 함수가 오면 연쇄 법칙이 붙는다. 그래서 ∇pθ(s) = pθ(s) ∇log pθ(s)가 된다.
4. 이것을 합 안에 넣으면 다시 기댓값 꼴이 된다. ∇E[R(s)] = E[R(s) ∇log pθ(s)]
5. 모든 s를 다 볼 수 없고 분포를 정확히 알 수도 없으니, 몬테카를로 방법으로 m개를 샘플링해 평균을 낸다.

갱신식은 다음과 같다. α는 학습률이다.

θ ← θ + α (1/m) Σ R(sᵢ) ∇log pθ(sᵢ)

식의 뜻은 단순하다. 샘플 sᵢ의 보상이 양수면 그 샘플이 생성될 확률을 높이는 방향으로 파라미터를 갱신한다. 보상이 클수록 더 많이 높인다. 보상이 음수면 반대 방향으로 갱신해서 확률을 낮춘다. 보상을 받은 행동은 강화하고 낮은 보상을 받은 행동은 억누르기 때문에 강화 학습이라고 부른다. 보상 함수를 θ에 대해 미분하지 않으므로 어떤 보상 함수든 쓸 수 있고, 이 방법이 잘 작동한다. 다만 학습이 빠르지 않은 어려움이 있었다.

## 점수를 매기게 하지 말고 둘 중 나은 것을 고르게 한다

사람이 매번 평가하는 것은 어노테이터에게 비용이 계속 든다. 그래서 사람의 선호를 예측하는 언어 모델을 따로 학습해 보상 모델로 쓰고, 사람 대신 이 모델의 출력을 목표로 삼는다.

또 하나의 문제는 사람의 점수에 노이즈가 많다는 것이다. 요약 하나를 보여 주고 몇 점이냐고 물으면 답하기 어렵고, 사람마다 척도가 다르다. 같은 답을 누구는 4.1점, 누구는 다른 점수로 매기는 식으로 보정이 안 된다. 점수를 직접 매기게 하는 대신 두 개를 주고 어느 쪽이 나은지 고르게 하는 쌍대 비교(pairwise comparison)가 더 믿을 만한 데이터를 모은다.

보상 모델은 이렇게 모은 순위 데이터로 Bradley-Terry 방식으로 학습한다. 예를 들어 순위가 s1, s3, s2 순서라고 하자. s1과 s3의 쌍에서 s1이 이긴 샘플, s3가 진 샘플이다. 손실 함수는 이긴 샘플의 점수에서 진 샘플의 점수를 뺀 차이가 양의 방향으로 커지도록 만든다. 학습 데이터는 비교 결과이지만, 모델의 출력은 답 하나에 점수 하나다.

이 보상 모델이 얼마나 효용이 있는지부터는 다음 시간에 이어서 한다.

10주차에는 트랜스포머를 블록 단위로 조립했는데, 이번 주는 그렇게 만든 모델을 사전 학습한 뒤에 무엇을 더 해야 쓸 수 있는 모델이 되는지였다. 사전 학습만 한 모델에 지시를 넣으면 답 대신 이어질 글을 생성한다는 예시가 출발점이었고, 인스트럭션 튜닝은 지시를 따르게 하는 단계, RLHF는 그중에서 사람이 선호하는 답을 고르게 하는 단계로 구분됐다. 평소에 쓰는 채팅형 모델이 이 두 단계를 거친 결과라고 보면 동작이 설명된다.

REINFORCE 유도는 보상 함수를 미분할 수 없다는 문제를 로그 미분으로 피해 가는 부분이 핵심이었다. 미분은 pθ에만 걸리고 R은 가중치처럼 곱해진다. 3주차의 역전파는 손실까지의 식을 연쇄 법칙으로 따라 미분하는 방법이었는데, 사람의 점수처럼 미분할 수 없는 신호로도 파라미터를 갱신할 수 있다는 점이 새로웠다.

Alpaca와 LIMA는 데이터를 어떻게 구하느냐의 이야기였다. 52,000개를 합성하는 방법과 1,000개를 잘 고르는 방법이 나란히 나왔는데, 둘 다 사전 학습이 잘 된 모델을 전제로 한다. 다음 시간에는 보상 모델의 효용과 PPO를 대신하는 DPO, 사람의 피드백을 AI로 바꾸는 방법이 남아 있다. 보상 모델을 속여 점수만 높이는 답이 나올 수 있는지도 보상 모델의 한계를 다룰 때 확인해 보려고 한다.
