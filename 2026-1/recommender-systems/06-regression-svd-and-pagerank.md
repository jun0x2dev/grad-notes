# 6주차: 유사도를 학습하고, 차원을 줄이고, 그래프로 보다

메모리 기반 추천의 남은 부분을 다뤘다. 지난주 끝에 예고했던 이웃 기반 방식의 회귀 관점을 제대로 설명하고, 차원 축소(SVD)로 계산량과 희소성 문제를 줄이는 방법을 봤다. 후반에는 사용자-아이템 관계를 그래프로 보고, 랜덤 워크와 페이지 랭크로 노드의 중요도까지 활용하는 방법을 배웠다.

## 유사도를 학습 가능한 가중치로 바꾸기

이웃 기반 예측 수식에서 s_jv(사용자 j가 아이템 v에 준 평균 중심화 평점)는 입력으로 고정된 값이고, 유사도 Sim(i, j)만 우리가 정할 수 있다. 결국 예측을 잘하려면 유사도를 잘 정해야 한다.

그래서 유사도를 유사도 함수로 계산하는 대신 학습 가능한 가중치 w_ij로 바꾼다.

```
r̂_iv = μ_i + Σ_{j ∈ P_i(v)} w_ij · s_jv
```

이러면 선형 회귀와 같은 모양이 된다. 예측값과 실제 평점의 제곱 오차를 모든 사용자, 모든 아이템에 대해 합한 걸 손실 함수로 두고 최소화한다. 각 가중치로 편미분해서 얻은 기울기(gradient)에 학습률(learning rate)을 곱해 가중치를 조금씩 고친다. 학습률을 크게 하면 최적점을 지나쳐 오히려 나빠질 수 있으니, 작게 조금씩 여러 번 고친다. 손실이 더 이상 줄지 않을 때까지 반복한다.

유사도 함수는 사용자 사이의 관계만 보지만, 학습된 가중치는 사용자와 아이템 사이의 상호 의존성까지 반영할 수 있다. 그리고 w_ij와 w_ji는 다를 수 있다. 타겟 사용자가 누구냐에 따라 같은 두 사람의 관계도 달라질 수 있다는 뜻이다.

## 회귀 방식의 문제와 보완

피어 그룹 P_i(v)는 아이템마다 크기가 다르다. 많은 사람이 평가한 아이템은 피어 그룹이 크고, 적게 평가된 아이템은 작다. 데이터가 희소해서 회귀 계수가 피어 그룹 크기에 크게 좌우되고, 관측된 값만으로 계속 학습하다 보면 과적합되기 쉽다.

이를 보완하는 방법이 세 가지 나왔다.

- 정규화 항(regularization term): 손실 함수 끝에 가중치 크기에 대한 항을 더한다. 과적합을 막는 일반적인 방법이고, 처음 보는 데이터를 예측하는 데 도움이 된다.
- 빈도로 나누기: 많은 사용자가 평가한 아이템은 다른 사람 평점의 영향을 많이 받으니, 피어 그룹 크기(빈도)로 나눠서 그 영향을 줄인다.
- 편향 항(bias term): 평균 평점 μ 대신 사용자 편향과 아이템 편향을 따로 두고 같이 학습한다. 원래 깐깐하게 평가하는 사용자, 원래 점수를 잘 받는 아이템이 있기 때문이다. 이렇게 하면 엄밀히는 선형 회귀라고 부르기 어렵지만 예측 정확도는 더 좋아진다.

아이템 기반도 똑같이 아이템 간 유사도를 가중치로 바꿔 회귀 모델로 풀 수 있다.

## 차원 축소: 평점 행렬을 압축하기

사용자를 평점 행렬의 행 벡터로 표현하면, 사용자 한 명을 나타내는 데 아이템 개수만큼의 차원이 필요하다. 아이템이 10만 개면 10만 차원이다. 그런데 그 대부분이 0이다. 이런 벡터끼리 유사도를 구하는 건 계산도 비싸고 메모리에 안 들어갈 수도 있다. 그리고 0이 너무 많아서 구한 유사도가 의미 있는지도 의문이다.

그래서 행과 열을 모두 압축한다. m×n 평점 행렬을 m×d 사용자 행렬과 d×n 아이템 행렬로 분해한다. d는 우리가 정하는 작은 값이다. 그러면 사용자 한 명을 d차원 벡터로 표현할 수 있고, 이 벡터는 0이 거의 없이 밀집(dense)되어 있다. 이걸 잠재 벡터(latent vector), 이 d차원 공간을 잠재 공간(latent space)이라고 한다. 각 차원이 무엇을 뜻하는지 설명하기는 어렵지만, 두 행렬을 곱했을 때 원래 평점 행렬에 가깝게 나오면 잘 분해된 것이고, 그 안의 값들은 의미가 있다고 볼 수 있다.

줄어든 벡터로 유사도를 구하면 계산이 훨씬 효율적이고, 희소성이 높은 상황에서 더 의미 있는 유사도를 얻을 수 있다. 여기까지는 여전히 메모리 기반이다. 행렬 분해 자체로 비어 있는 평점을 바로 예측하는 건 모델 기반이고, 나중에 배운다.

## 특이값 분해 (SVD)

차원 축소 알고리즘은 여러 가지가 있고, 그중 행렬 분해(matrix factorization)의 대표가 특이값 분해(singular value decomposition)다. 행렬 M을 세 행렬로 분해한다.

```
M = U Σ Vᵀ
```

- U: 왼쪽 특이 벡터(left singular vectors)로 이루어진 직교 행렬
- Σ: 특이값(singular values)이 대각선에 있는 대각 행렬. 특이 벡터들이 얼마나 늘어나거나 줄어드는지를 나타내는 스케일링 값이다.
- Vᵀ: 오른쪽 특이 벡터(right singular vectors)로 이루어진 직교 행렬

차원을 줄이려면 Σ에서 0이 아닌 특이값만 남기고(compact SVD), 다시 그중 가장 큰 d개만 남긴다(truncated SVD). 남긴 특이값에 맞춰 U는 열을, Vᵀ는 행을 잘라 낸다. 세 행렬을 곱하면 원래 M에 가까운 행렬이 나온다. scikit-learn 같은 프레임워크로 SVD를 돌리면 보통 truncated SVD를 쓰게 된다.

예제에서는 사용자를 원래 4차원에서 3차원으로, 아이템을 6차원에서 3차원으로 줄여서 표현했다. 이렇게 얻은 축소된 표현으로 사용자나 아이템 간 유사도를 구하고, 피어 그룹을 만들고, 이웃 기반 방식으로 평점을 예측하면 된다.

## 사용자-아이템 관계를 그래프로 보기

지금까지는 모든 사용자와 아이템을 같은 중요도로 다뤘다. 클러스터링과 차원 축소는 주로 계산량을 줄이는 방법이었다. 그런데 희소성 때문에 유사도를 제대로 구하기 어려운 문제는 여전히 남아 있다.

평점 행렬은 그래프로 바꿀 수 있다. 사용자와 아이템을 노드로, 상호작용을 간선(edge)으로 두면 방향 없는 이분 그래프(bipartite graph)가 된다. 그래프로 보면 두 사용자가 같은 아이템을 많이 평가하지 않았더라도 짧은 경로가 여러 개 있으면 이웃으로 볼 수 있다. 직접 겹치지 않아도 간접적으로 연결된 정보를 쓸 수 있어서, 희소한 데이터에서 이웃을 정의하는 데 유용하다.

## 랜덤 워크

랜덤 워크(random walk)는 그래프에서 한 노드에서 출발해 연결된 노드 중 하나로 무작위로 이동하기를 반복하는 것이다. 무작위로 이동하기 때문에 간접적인 연결 정보를 얻을 수 있다. 정해야 할 변수는 네 가지다.

- 최대 스텝 수
- 사용자 노드에서 아이템 노드로 이동할 확률
- 아이템 노드에서 사용자 노드로 이동할 확률
- 언제 멈출지에 대한 조건

스텝 수를 정하지 않으면 어떤 사용자는 끝없이 긴 경로가, 어떤 사용자는 갈 데가 없어서 아주 짧은 경로가 나온다. 각 사용자 노드에서 랜덤 워크를 하면 사용자와 아이템이 섞인 노드 시퀀스가 하나씩 나온다. 시간 개념은 없다.

이걸로 사용자 간 유사도를 구할 수 있다. 각 사용자의 랜덤 워크에 들어 있는 아이템 집합을 만들고 자카드 유사도(Jaccard similarity)를 구한다. 교집합 크기를 합집합 크기로 나눈 값이다.

- 사용자 1의 워크에 나온 아이템: {1, 2}
- 사용자 2의 워크에 나온 아이템: {1, 3}
- 합집합 {1, 2, 3}은 3개, 교집합 {1}은 1개라서 유사도는 1/3

랜덤 워크는 이런 용도로만 쓰는 게 아니고, 나중에 그래프 신경망(GNN)을 다룰 때 다시 나온다고 했다.

## 페이지 랭크

페이지 랭크(PageRank)는 그래프에서 노드의 중요도를 계산하는 링크 분석 알고리즘이다. 원래 추천 시스템용이 아니라 웹 검색용으로 나왔는데, 노드 중요도를 구하는 방식이 추천에도 잘 맞는다.

이름은 구글 창업자 래리 페이지에서 왔다. 스탠퍼드 석사 과정 중 프로젝트에서 나온 알고리즘이 구글 검색의 핵심이 됐다. 초창기 웹은 야후처럼 사람이 직접 카테고리로 분류했고, 그다음에는 텍스트 키워드가 맞는지로 문서를 찾았다. 하지만 웹이 너무 크고 신뢰하기 어려운 문서와 스팸이 많아서 키워드 일치만으로는 품질이 낮았다. 페이지의 평판을 판단할 방법이 필요했다.

가정은 이렇다.

- 신뢰할 만한 페이지들은 서로를 참조(링크)한다.
- 모든 페이지가 같은 중요도를 갖지는 않는다. 대학 홈페이지와 개인 연구실 홈페이지는 중요도가 다르다.

### 링크를 투표로 보기

링크에는 나가는 링크(out-link)와 들어오는 링크(in-link)가 있다. 페이지 랭크는 들어오는 링크를 투표로 본다. 들어오는 링크가 많을수록 중요한데, 모든 투표의 무게가 같지는 않다. 중요한 페이지에서 받은 링크일수록 무게가 크다.

각 링크의 투표 값은 출발 노드의 중요도를 그 노드의 나가는 링크 수로 나눈 값이다. 중요도가 r_k인 노드 k가 나가는 링크를 4개 갖고 있으면, 각 링크의 값은 r_k / 4다. 어떤 노드의 중요도는 들어오는 링크들의 투표 값을 모두 더한 것이다.

```
r_j = Σ_{i → j} r_i / d_i
```

d_i는 노드 i의 나가는 링크 수다. 노드마다 이 식(flow equation)을 세우면 미지수가 노드 수만큼 있는 연립방정식이 된다. 이대로는 해가 하나로 정해지지 않으니, 모든 노드의 중요도 합이 1이라는 제약을 추가한다. 노드 3개짜리 예제에서는 이렇게 풀어서 노드 y의 중요도가 2/5로 나왔다.

노드가 몇 개 안 될 때는 이렇게 직접 풀면 되지만, 웹처럼 큰 그래프에서는 다른 방법이 필요하다.

### 행렬로 풀기

열 확률 행렬(column stochastic matrix) M을 만든다. 노드 i가 나가는 링크를 d_i개 갖고 있고 i에서 j로 링크가 있으면 M_ji = 1/d_i, 링크가 없으면 0이다. 각 열의 합은 1이다. 예를 들어 나가는 링크가 3개인 노드의 열에는 1/3이 세 개 들어간다. M은 그래프가 주어지면 바로 만들 수 있다.

랭크 벡터 r은 각 노드의 중요도를 담은 벡터이고, 원소의 합이 1이다. 그러면 flow equation은 행렬-벡터 곱으로 쓸 수 있다.

```
r = M · r
```

r은 M의 고유값 1에 대한 고유 벡터(eigenvector)다. M이 열의 합이 1인 확률 행렬이라 가장 큰 고유값이 1이 된다.

### 파워 반복 (Power Iteration)

r을 효율적으로 구하는 방법이다.

1. 노드가 N개면 모든 노드의 중요도를 1/N로 초기화한다. 처음에는 다 똑같이 중요하다고 가정한다.
2. r(t+1) = M · r(t)로 갱신한다.
3. r(t+1)과 r(t)의 원소별 차이의 합(L1 norm)이 거의 0이 될 때까지 반복한다.

수렴한 r의 값이 각 노드의 중요도다. 예제에서도 1/3씩으로 시작해서 몇 번 반복하자 값이 거의 변하지 않았다.

### 추천에서는 어떻게 쓰나

수업 끝에 웹 페이지 예제로 갑자기 넘어와서 추천과 어떻게 연결되는지 헷갈린다는 질문이 나왔다. 페이지 랭크는 노드의 중요도를 구하는 방법이고, 그래프를 입력으로 받는 그래프 신경망에서 노드의 특징뿐 아니라 그 노드가 얼마나 중요한지까지 정보로 넘겨주는 식으로 활용된다고 했다. 차원 축소에 대해서도 비슷한 질문이 있었는데, 축소된 벡터는 예측 단계에서 쓸 유사도를 더 정확하고 효율적으로 구하는 데 쓴다는 답이었다.

## 회고

유사도를 학습하자는 아이디어는 지난주 예고로 들었을 때보다 이번에 더 명확해졌다. 피어슨 상관계수 같은 유사도 함수는 사람이 정한 규칙이고, 그 자리를 가중치로 바꾸면 데이터가 직접 정하게 된다. 그리고 그렇게 바꾸는 순간 과적합, 정규화, 편향 항 같은 머신러닝의 문제들이 그대로 따라온다. 메모리 기반에서 모델 기반으로 넘어가는 경계가 여기쯤인 것 같다.

SVD는 선형대수 수식보다 "10만 차원 중 대부분이 0인 벡터를 0이 거의 없는 작은 벡터로 압축한다"는 설명이 와닿았다. 두 행렬을 곱해서 원래 행렬이 잘 복원되면 압축이 잘된 것이라는 기준도 직관적이다.

그래프 쪽은 희소성 문제를 다르게 푸는 방식이라 흥미로웠다. 두 사용자가 같은 글을 하나도 안 읽었어도, 경로가 이어져 있으면 비슷하다고 볼 수 있다. GrowTechStack처럼 사용자마다 읽은 글이 몇 개 안 되는 서비스라면 직접 겹치는 걸로 유사도를 구하기는 어려울 것이다. 사용자와 글을 그래프로 놓고 간접 연결을 쓰는 방식이 더 현실적일 수 있겠다.

페이지 랭크는 이름만 알던 알고리즘이었는데, 직접 flow equation을 세우고 행렬로 바꿔 파워 반복까지 해 보니 생각보다 단순했다. 중요한 노드에서 받은 링크가 더 무겁다는 재귀적인 정의가 반복 계산으로 자연스럽게 풀린다.
