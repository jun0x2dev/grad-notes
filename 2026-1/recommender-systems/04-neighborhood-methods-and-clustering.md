# 4주차: 이웃 기반 추천을 손으로 계산해 보고, 왜 느린지 알게 되다

지난주에 수식으로만 본 사용자 기반 예측을 예제로 직접 계산했다. 이어서 유사도를 보정하는 방법들, 아이템 기반 방식, 둘의 장단점을 보고, 이웃 기반 방식이 왜 느린지와 그걸 클러스터링으로 줄이는 방법까지 다뤘다. 마지막에 이웃 기반 방식을 선형 회귀로 바라보는 관점을 소개하고 끝났다.

## 사용자 기반 예측을 직접 계산하기

사용자 5명, 아이템 6개의 평점 행렬에서 사용자 3이 아이템 1과 아이템 6에 줄 평점을 예측했다. 사용자 3이 실제로 준 평점은 3, 3, 1, 1이라 평균이 2다.

먼저 사용자 3과 나머지 사용자들의 유사도를 구한다. 이때 각 사용자의 평균 평점을 미리 구해 두면 편하다. 유사도는 두 사용자가 같이 평가한 아이템만으로 계산한다.

비교를 위해 평균을 빼지 않은 그냥 코사인 유사도도 구했다. 사용자 1과 3의 코사인 유사도는 0.956으로 아주 높게 나왔다. 하지만 이건 사용자마다 점수 범위와 평균이 다르다는 걸 전혀 고려하지 않은 값이다. 피어슨 상관계수로 다시 구하면 각 평점에서 평균을 빼고 계산하니까 상대적인 선호 패턴만 남는다. 코사인 유사도는 0~1 범위인 반면, 피어슨은 −1~1이라 관계의 방향까지 알 수 있다.

피어 그룹은 예측하려는 아이템을 평가한 사용자 중에서 뽑아야 한다. 이 예제에서는 사용자 3을 뺀 나머지가 모두 아이템 1과 6을 평가했기 때문에 그냥 유사도가 높은 2명을 뽑았다. 피어 그룹 크기 k는 하이퍼파라미터라서 우리가 정한다.

여기서 평균 중심화를 안 하고 피어 그룹의 실제 평점으로 바로 가중 평균을 내면 아이템 1은 6.49, 아이템 6은 4가 나온다. 사용자 3은 지금까지 1~3점만 줬는데 갑자기 6.49라는 건 말이 안 된다. 평소보다 두 배 좋아한다고 볼 근거가 없다.

평균 중심화한 평점(실제 평점 − 그 사용자 평균)으로 가중 평균을 내고, 마지막에 사용자 3의 평균 2를 더하면 아이템 1은 3.35, 아이템 6은 0.86이 나온다. 사용자 3의 평소 점수 범위 안에서 납득할 수 있는 값이다.

수업 중에 k를 4로 하면 어떻게 되냐는 질문이 있었다. 그러면 음의 상관관계에 있는 사용자도 피어 그룹에 들어온다. 피어 그룹을 뽑을 때 피어슨 대신 코사인을 써도 되는데, 그러면 순위가 달라져서 뽑히는 사용자가 바뀔 수 있다. 어느 쪽을 쓸지도 결국 설계하는 사람이 정한다.

## 유사도를 보정하는 방법들

유의도 가중치(significance weighting)는 두 사용자가 같이 평가한 아이템이 적을 때 쓴다. 한두 개가 우연히 겹쳐서 유사도가 높게 나왔다고 둘이 비슷하다고 보기는 어렵다. 그래서 공통 평점 개수가 정해 둔 기준값 β보다 적으면 유사도를 할인한다.

Z-score 정규화는 평균 중심화에서 한 걸음 더 나간다. 평균을 뺀 값을 표준편차로 한 번 더 나눠서 사용자마다 점수를 퍼뜨리는 정도까지 맞춘다.

피어 그룹 필터링도 있다. k를 정해 두면 유사도가 약하거나 음수인 사용자도 피어 그룹에 들어올 수 있고, 그러면 예측 오차가 커진다. 그래서 k가 정해져 있더라도 상관관계가 약하거나 음수인 사용자는 걸러 낸다.

## 롱테일과 IDF 가중치

인기 아이템은 많은 사용자가 평가하니까 거의 모든 사용자 쌍의 공통 아이템에 들어간다. 그러면 사용자마다 다른 취향을 구분하기가 어려워지고 추천 품질이 떨어진다.

가장 기본적인 해결책은 인기 아이템과 비인기 아이템의 가중치를 다르게 두는 것이다. 텍스트 분석의 IDF(inverse document frequency) 개념을 그대로 가져온다.

```
w_v = log(m / m_v)
```

m은 전체 사용자 수, m_v는 아이템 v를 평가한 사용자 수다. 많은 사람이 평가한 아이템일수록 가중치가 작아진다. 텍스트에서 모든 문서에 다 나오는 단어의 중요도를 낮추는 것과 같은 원리다. 유사도를 계산할 때 각 아이템에 이 가중치를 곱한다.

## 아이템 기반 이웃 모델

아이템 기반은 모든 걸 뒤집어서 생각하면 된다. 피어 그룹이 사용자가 아니라 아이템이고, 행 벡터가 아니라 열 벡터끼리 유사도를 구한다.

유사도는 조정 코사인(adjusted cosine)을 쓴다. 각 평점에서 그 평점을 준 사용자의 평균을 뺀 다음 코사인 유사도를 구하는 것이다. 사용자마다 척도가 다른 문제는 아이템 기반에서도 똑같이 있기 때문이다.

수업 중에 피어슨과 조정 코사인이 수식상 거의 같은데 왜 이름이 다르냐는 질문이 나왔다. 피어슨은 평균을 빼는 걸 기본으로 갖고 있는 수식이고, 조정 코사인은 코사인에 평균 중심화를 추가로 적용했다는 뜻이다. 둘 다 사용자별 편향과 척도 차이를 해결하려는 거라 헷갈릴 필요는 없다고 했다.

같은 예제로 계산하면 아이템 1과 비슷한 아이템은 아이템 2(0.735)와 아이템 3(0.912)이다. 예측할 때는 사용자 3 본인이 아이템 2와 3에 준 평점(3, 3)만 쓴다. 결과는 약 3이다. 아이템 6은 아이템 4, 5와 비슷하게 나왔고, 사용자 3이 둘 다 1을 줬기 때문에 예측은 약 1이다. 사용자 기반 결과(3.35, 0.86)와 비슷하다.

## 사용자 기반 vs 아이템 기반

아이템 기반의 장점은 다음과 같다.

- 예측에 본인 평점만 쓰기 때문에 더 개인화된 결과가 나온다.
- 추천 이유를 설명하기 쉽다. "당신이 좋아한 이 아이템과 비슷해서"라고 말할 수 있다. 사용자 기반은 다른 사람의 평점을 근거로 들어야 해서 개인정보 문제도 걸린다.
- 더 안정적이다. 보통 사용자가 아이템보다 훨씬 빨리 늘어난다. 두 사용자가 같이 평가한 아이템보다 두 아이템을 같이 평가한 사용자가 훨씬 많을 가능성이 높아서 유사도가 덜 흔들리고, 새 사용자가 들어와도 아이템 간 유사도는 크게 바뀌지 않는다.

사용자 기반의 장점은 다양성이다. 다른 사람들의 취향이 반영되니까 뜻밖의 아이템을 추천받을 수 있다. 아이템 기반은 본인이 이미 좋아했던 것과 비슷한, 뻔한 아이템을 추천하기 쉽다.

## 이웃 기반 방식은 왜 느린가

이웃 기반 방식은 두 단계로 나뉜다.

- 오프라인 단계: 모든 사용자 쌍(또는 아이템 쌍)의 유사도를 구하고 피어 그룹을 만든다.
- 온라인 단계: 만들어 둔 유사도와 피어 그룹으로 예측한다.

문제는 오프라인 단계다. 사용자 기반이면 모든 사용자 쌍을 비교해야 하니 사용자 수의 제곱에 비례하고, 쌍마다 평점 벡터를 훑는 비용이 곱해진다. 아이템 기반도 아이템 수의 제곱에 비례한다. 사용자나 아이템이 많아지면 시간과 공간이 감당할 수 없이 커진다. 온라인 단계는 피어 그룹 k개만 보면 되니 상대적으로 가볍다.

정리하면 이웃 기반 방식은 단순하고 구현하기 쉽고, 추천 근거를 설명할 수 있고, 새 데이터가 들어와도 추천이 비교적 안정적이다. 대신 규모가 커지면 오프라인 단계가 비현실적이 되고, 데이터가 희소해서 예측할 수 있는 범위(coverage)도 제한된다.

## 클러스터링으로 비교 대상을 줄이기

한 사용자와 나머지 전체 사용자를 다 비교하는 대신, 먼저 클러스터링으로 비슷한 사용자끼리 묶는다. 그다음 예측할 때는 그 사용자가 속한 클러스터 안에서만 이웃 기반 방식을 쓴다. 1만 명을 다 비교할 걸 클러스터 안의 100명만 비교하면 된다. 클러스터링 자체에도 비용이 들지만 전체를 다 비교하는 것보다 훨씬 낫다.

정확도까지 좋아지는지는 보장할 수 없다는 질문과 답이 있었다. 장점은 시간 복잡도이고, 데이터가 잘 묶이지 않으면 오히려 문제가 된다.

### K-means

가장 대표적인 클러스터링 알고리즘이다.

1. 클러스터 개수 k를 정한다.
2. k개의 중심점(centroid)을 찍는다. 처음에는 무작위로 찍을 수 있다.
3. 각 데이터 포인트를 가장 가까운 중심점의 클러스터에 할당한다.
4. 각 클러스터에 속한 포인트들의 가운데로 중심점을 옮긴다.
5. 중심점이 더 이상 움직이지 않을 때까지 3~4를 반복한다.

### 최적의 k 고르기

k가 너무 크면 클러스터링을 안 한 것과 같다. 좋은 k는 클러스터 안의 포인트들은 서로 뭉쳐 있고, 클러스터끼리는 멀리 떨어지게 만드는 값이다. 정해진 답은 없고 경험적인 기준도 있지만, 대표적으로 엘보 방법(elbow method)을 쓴다.

1. k를 1부터 늘려 가며 K-means를 돌린다.
2. 매번 WCSS(within-cluster sum of squares)를 구한다. 각 클러스터에서 중심점과 포인트들 사이 거리의 제곱을 다 더한 값으로, 클러스터 안에서 포인트가 얼마나 퍼져 있는지(dispersion)를 나타낸다.
3. k가 커질수록 WCSS는 줄어드는데, 어느 순간부터는 거의 안 줄어든다. 그래프가 팔꿈치처럼 꺾이는 그 지점이 적절한 k다.

### K-means++

처음 중심점을 어디에 찍느냐에 따라 결과와 수렴 속도가 달라진다. 중심점들이 처음부터 서로 멀리 떨어져 있으면 좋다. K-means++는 알고리즘은 K-means와 같고 초기화만 다르다.

1. 데이터 포인트 중 하나를 무작위로 골라 첫 중심점으로 한다.
2. 이미 고른 중심점들에서 가장 멀리 있는 포인트를 다음 중심점으로 한다.
3. k개가 될 때까지 반복한다.

수렴이 더 빠르다.

## 이웃 기반 방식을 선형 회귀로 보기

다음 주 내용의 예고로 짧게 다뤘다. 사용자 기반 예측 수식을 다시 보면, 피어 그룹 사용자들의 평점에 유사도를 곱해서 더하는 선형 결합(weighted linear combination)이다. 선형 회귀와 같은 모양이다.

```
ŷ = w_0 + w_1·x_1 + w_2·x_2 + ... + w_t·x_t
```

- y: 예측할 평점 (종속 변수)
- x: 다른 사용자들의 평점 (독립 변수, 관측값)
- w: 가중치. 이웃 기반에서는 유사도가 이 자리에 있다.

이웃 기반 방식은 이 w를 유사도 함수로 휴리스틱하게 정해 버린다. 그런데 실제로는 사용자와 사용자 사이뿐 아니라 사용자와 다른 아이템들 사이의 의존성까지 반영해야 정확하게 예측할 수 있다. 그래서 유사도를 학습 가능한 계수로 두고, 예측값과 실제 평점의 차이(MSE)를 최소화하도록 학습하자는 것이다. 학습은 손실 함수를 각 가중치로 편미분해서 얻은 변화율에 학습률을 곱해 가중치를 조금씩 고치는 방식(경사 하강법)으로 한다.

학습된 가중치 w_ij는 w_ji와 다를 수 있다. 타겟 사용자가 누구냐에 따라 관계가 달라지기 때문이다. 이 이야기는 다음 주에 이어서 한다고 했다.

## 회고

지난주에 수식으로 봤을 때는 평균을 빼고 다시 더하는 게 번거로운 절차처럼 보였는데, 예제에서 6.49가 나오는 걸 보고 바로 이해가 됐다. 1~3점만 주던 사람에게 6.49를 예측하는 건 계산은 맞아도 의미가 없다. 평균 중심화는 "이 사람 기준으로 얼마나 좋아하는가"로 바꿔서 계산하고, 마지막에 그 사람의 척도로 되돌리는 과정이었다.

아이템 기반이 설명하기 쉽다는 점은 실제 서비스 입장에서 중요해 보였다. "이 글을 읽었으니 이 글도"는 바로 납득이 되지만, "당신과 비슷한 사람이 이 글을 읽었으니"는 근거를 보여 주기 어렵고 다른 사람의 기록을 꺼내야 한다. GrowTechStack처럼 글이 매시간 늘어나는 서비스라면 아이템이 사용자보다 빨리 늘 수도 있어서, 아이템 기반이 더 안정적이라는 설명이 그대로 맞지는 않을 것 같다. 도메인마다 다르다는 말이 이런 뜻인 것 같다.

오프라인 단계가 제곱으로 커진다는 걸 보니, 모든 쌍을 미리 계산해 두는 방식은 규모가 커지면 한계가 분명하다. 클러스터링으로 비교 대상을 줄이는 건 정확도를 조금 내주고 속도를 얻는 선택이다. 마지막의 선형 회귀 이야기는 유사도를 사람이 정하지 말고 학습하자는 건데, 모델 기반 방식으로 넘어가는 다리 역할을 하는 것 같다.
