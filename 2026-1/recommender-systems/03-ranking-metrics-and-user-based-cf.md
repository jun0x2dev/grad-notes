# 3주차: 순위까지 평가하고, 비슷한 사용자를 찾기 시작하다

지난주에 이어 평가 지표를 마무리했다. 분류 지표(F1, AUC)를 짧게 정리한 뒤, 추천 결과를 순위로 보여 줄 때 쓰는 랭킹 지표를 배웠다. 후반부터는 드디어 실제 추천 방법으로 들어가서, 메모리 기반 추천과 사용자 기반 이웃 모델의 유사도 계산까지 봤다.

## 추천은 순위로 나온다

요즘 추천 시스템은 아이템 하나만 딱 추천하지 않는다. 1위부터 순위를 매긴 목록을 만들고, 그중 상위 k개를 보여 준다. k는 설정하기 나름이다. 높은 평점을 받을 아이템일수록 순위가 높아야 한다.

지난주에 본 정밀도와 재현율은 맞혔는지만 보고 순위는 전혀 고려하지 않는다. 그래서 순위를 반영하는 지표가 따로 필요하다. 수식은 복잡해 보여도 예제로 보면 쉽다.

## Hit@k

가장 단순하고 많이 쓰는 지표다. 상위 k개 안에 사용자가 실제로 좋아하는 아이템이 하나라도 있으면 hit(1), 없으면 0이다.

k = 5일 때 예제를 봤다.

- 사용자 1: 상위 5개 중 3개가 좋아하는 아이템이라 hit
- 사용자 2: 6위부터는 잘 맞혔지만 상위 5개 안에는 하나도 없어서 hit 아님
- 사용자 3: 1~4위는 다 틀렸지만 5위에 좋아하는 아이템이 있어서 hit

순위가 1위든 5위든, 6위 아래를 얼마나 잘 맞혔든 상관없다. 결과는 3명 중 2명이 hit라서 2/3이다.

## Precision@k, Recall@k

상위 k개는 "좋아할 거라고 예측한 것", 나머지는 "안 좋아할 거라고 예측한 것"으로 보고 정밀도와 재현율을 구한다.

사용자 1은 상위 5개 중 3개를 맞혔고(TP = 3), 2개는 틀렸다(FP = 2). 좋아하는 아이템 중 하나는 상위 5개 밖에 있다(FN = 1).

- Precision@5 = 3 / (3 + 2) = 3/5
- Recall@5 = 3 / (3 + 1) = 3/4

사용자 3은 상위 5개 중 1개만 맞혔고, 좋아하는 아이템이 하나 더 아래에 있다.

- Precision@5 = 1/5
- Recall@5 = 1/2

여전히 상위 5개 안에서의 순서는 고려하지 않는다.

## AP@k와 MAP

평균 정밀도(Average Precision@k)는 순위와 정밀도를 같이 반영한다. 위에서부터 한 칸씩 내려가면서 그 지점까지의 정밀도를 구하고, 맞힌 위치들의 정밀도를 평균 낸다. 맞힌 아이템이 위쪽에 몰려 있을수록 값이 커진다.

사용자 1처럼 1~3위를 연달아 맞히면 각 지점의 정밀도가 1/1, 2/2, 3/3으로 높게 유지된다. 반대로 사용자 2처럼 위쪽을 다 틀리고 아래에서 맞히면 1/1이 아니라 0/1, 0/2, 1/3, 2/4, 3/5처럼 시작부터 낮다.

MAP(Mean Average Precision)는 사용자별 AP@k를 평균 낸 것이다.

## DCG와 NDCG

지금까지의 지표는 맞힌 아이템을 모두 같은 무게로 봤다. 그런데 같은 "좋아함"이라도 어떤 아이템은 5점, 어떤 아이템은 3점일 수 있다. DCG는 이 차이까지 반영한다.

먼저 누적 이득(CG, Cumulative Gain)은 상위 k개 아이템의 관련성 점수(relevance score)를 다 더한 것이다. 관련성 점수로는 보통 사용자-아이템 행렬의 실제 평점을 그대로 쓴다. 안 좋아하는 아이템은 0이다.

DCG(Discounted Cumulative Gain)는 여기에 순위에 따른 할인을 넣는다.

```
DCG@k = Σ_{i=1..k} rel_i / log₂(i + 1)
```

i는 순위다. 1위가 가장 큰 가중치를 받고, 순위가 내려갈수록 분모가 커져서 가중치가 줄어든다. 수업에서 두 가지를 짚었다.

- 왜 로그를 쓰는가: 그냥 1/i로 나누면 1, 0.5, 0.33으로 너무 급격하게 줄어든다. 로그를 씌우면 점진적으로 줄어든다. 유일한 방법은 아니지만 가장 자연스럽다.
- 왜 1을 더하는가: log₂(1) = 0이라서 1위의 분모가 0이 되어 버린다. 1을 더하면 1위의 분모가 log₂(2) = 1이 된다.

NDCG(Normalized DCG)는 DCG를 정규화한 것이다. 먼저 상위 k개를 관련성 점수가 큰 순서대로 다시 정렬해서 DCG를 구한다. 이게 가장 이상적인 순서일 때의 값이라 IDCG(Ideal DCG)라고 부른다. 실제 DCG를 IDCG로 나누면 NDCG다.

```
NDCG@k = DCG@k / IDCG@k
```

IDCG는 같은 아이템들로 낼 수 있는 가장 큰 DCG라서 NDCG는 항상 0과 1 사이다. 1에 가까울수록 좋다. 순위가 중요한 추천 시스템에서는 필수로 쓰는 지표다.

수업 중에 "왜 굳이 IDCG로 나누는 게 정규화인가"라는 질문이 나왔다. 교수님도 처음엔 당연한 수식으로 받아들였다고 했다가, 수업 끝 무렵에 정리해 줬다. IDCG는 순서만 바꿔서 낼 수 있는 최댓값이니, 최댓값으로 나누면 0~1로 정규화되는 게 맞다는 것이다.

## MRR

역순위 평균(Mean Reciprocal Rank)은 사용자가 좋아하는 아이템이 처음 나타난 순위의 역수를 평균 낸다. 가장 관련 있는 아이템을 얼마나 빨리 보여 주는지 평가할 때 쓴다.

- 사용자 1: 처음 맞힌 아이템이 2위라서 1/2
- 사용자 2: 처음 맞힌 아이템이 4위라서 1/4
- MRR = (1/2 + 1/4) / 2 = 0.375

## 지표 정리

| 문제 | 주로 쓰는 지표 |
|---|---|
| 평점 예측 (회귀) | MSE, RMSE, MAE |
| 순위까지 보는 추천 (분류) | Recall@k, NDCG@k, MAP, MRR |

논문에서는 보통 여러 지표를 표로 같이 보고한다. 교수님은 예시로 든 논문에서 모든 지표에서 기존 최고 성능(SOTA)을 이겼다는 결과는 오히려 믿기 어렵다고 했다. 결국 지표 하나로는 모델을 온전히 평가할 수 없고, 여러 지표를 같이 봐야 한다.

## 롱테일 문제

사용자-아이템 상호작용 데이터는 불균형하고 희소하다. 소수의 인기 아이템이 상호작용 대부분을 받고, 나머지 대다수 아이템은 상호작용이 적은 롱테일(long-tail) 분포를 따른다. 그냥 학습하면 추천이 인기 아이템 쪽으로 쏠린다.

롱테일 분포 자체는 어쩔 수 없지만, 모델을 설계할 때나 평가할 때 이걸 고려해야 한다. 꼬리 쪽 아이템도 추천할 가치가 있을 수 있기 때문이다. 그래서 2주차에 나온 고려 사항이 여기서 다시 나온다.

- 참신성: 늘 하던 것만 말고 새로운 아이템도 추천한다.
- 다양성: 여러 종류의 아이템을 추천한다.
- 우연성: 사용자가 생각지도 못한 걸 추천해서 만족도를 높인다.
- 확장성: 사용자와 아이템이 많으니 대규모 데이터를 처리할 수 있어야 한다.

## 메모리 기반 추천: 유유상종

여기서부터 실제 추천 방법이다. 협업 필터링은 아이템 특징만 보는 게 아니라, 비슷한 사용자를 찾고 그 사람들이 무엇을 좋아했는지 보고 추천한다. 가정은 유유상종이다. 취향이 비슷한 사람들은 같은 아이템에 비슷한 평점을 준다. 아이템도 마찬가지로, 잘 만든 아이템은 대체로 높은 평점을 받고 못 만든 아이템은 낮은 평점을 받는다.

메모리 기반 추천은 협업 필터링을 위해 만든 가장 전통적인 알고리즘이고, 사용자 기반과 아이템 기반 두 가지가 있다. 사용자 기반을 이해하면 아이템 기반은 따라온다고 했다.

사용자 4가 아이템 3에 줄 평점을 예측한다고 하자.

사용자 기반은 이렇게 한다.

1. 사용자 4가 이미 평가한 아이템(예: 아이템 1, 5)을 평가한 다른 사용자들을 찾는다. 이때 아이템 3은 보지 않는다.
2. 그 사용자들과 사용자 4가 얼마나 비슷한지 유사도 함수로 점수를 매긴다.
3. 유사도 상위 k명을 뽑는다. 이걸 피어 그룹(peer group)이라고 한다.
4. 피어 그룹이 아이템 3에 준 평점으로 예측한다. 기본 아이디어는 평균이다.

아이템 기반은 차원만 바꾼다.

1. 아이템 3의 열 벡터와 가장 비슷한 아이템들을 찾는다. 예를 들어 아이템 1과 5가 뽑혔다.
2. 사용자 4가 아이템 1과 5에 준 평점으로 예측한다.

가장 큰 차이는 예측 단계다. 아이템 기반은 아이템끼리 유사도를 구할 때는 다른 사람들의 평점을 쓰지만, 예측할 때는 그 사용자 본인의 평점만 본다.

## 사용자 유사도를 구할 때의 문제

사용자끼리 행 벡터를 비교하면 몇 가지 문제가 생긴다.

- 평점 척도가 사람마다 다르다. 어떤 사람은 1~5점, 어떤 사람은 1~10점으로 매길 수 있다. 같은 점수라도 한 사람에게는 높은 점수, 다른 사람에게는 낮은 점수일 수 있다.
- 평가 성향이 다르다. 모든 아이템에 5점을 주는 관대한 사람과 1점만 주는 깐깐한 사람은 점수만 봐서는 선호를 알 수 없다. 둘 다 아이템 사이에 상대적인 선호 차이가 드러나지 않는다.
- 데이터가 희소하다. 두 사용자가 같이 평가한 아이템이 거의 없거나 아예 없을 때가 많다.

앞의 두 문제는 평균 중심화(mean-centering)로 어느 정도 해결한다. 각 사용자의 평점에서 그 사용자의 평균 평점을 빼는 것이다. 그러면 절대 점수가 아니라 상대적으로 무엇을 더 좋아했는지를 비교하게 된다. 희소성은 해결할 방법이 없고, 그런 한계가 있다고 받아들여야 한다.

## 피어슨 상관계수

표기부터 정리했다. u는 사용자, v는 아이템이다. I_u는 사용자 u가 상호작용한 아이템 집합이고, I_i ∩ I_j는 두 사용자가 같이 평가한 아이템 집합이다.

사용자 u의 평균 평점은 u가 평가한 모든 아이템의 평점을 더해서 개수로 나눈 것이다.

```
μ_u = Σ_{k ∈ I_u} r_uk / |I_u|
```

피어슨 상관계수(Pearson correlation coefficient)는 두 변수가 얼마나 선형적으로 관련 있는지, 그 방향까지 나타낸다. 두 변수의 공분산을 각 표준편차의 곱으로 나눈 값이다. 여기서는 두 사용자가 두 변수다.

```
Sim(i, j) = Σ_{k ∈ I_i ∩ I_j} (r_ik − μ_i)(r_jk − μ_j)
            / ( √Σ(r_ik − μ_i)² · √Σ(r_jk − μ_j)² )
```

값은 −1에서 1 사이다. 1에 가까우면 취향이 비슷하고, −1에 가까우면 반대이고, 0이면 관계가 없다. 누가 점수를 높게 주는지가 아니라 상대적으로 어떤 아이템을 더 좋아하는지를 본다.

헷갈리기 쉬운 부분을 짚어 줬다. 평균 평점 μ는 교집합이 아니라 그 사용자가 평가한 모든 아이템으로 구한다. 교집합은 피어슨 상관계수의 합을 계산할 때만 쓴다. 교집합 아이템만으로 평균을 내는 자료도 있지만 일반적이지 않다고 했다.

## 피어 그룹으로 평점 예측하기

유사도를 구했으면 예측을 한다.

1. 각 평점을 평균 중심화한다. s_uv = r_uv − μ_u
2. 아이템 v를 평가한 사용자 중 사용자 i와 유사도가 높은 상위 k명으로 피어 그룹 P_i(v)를 만든다.
3. 피어 그룹 사용자들의 중심화된 평점을 유사도로 가중 평균한다.
4. 마지막에 사용자 i의 평균 평점을 다시 더한다.

```
r̂_iv = μ_i + Σ_{j ∈ P_i(v)} Sim(i, j) · s_jv / Σ_{j ∈ P_i(v)} |Sim(i, j)|
```

4번이 중요하다. 계산 내내 평균을 뺀 값으로 다뤘기 때문에, 평균을 다시 더해 줘야 사용자 i의 평점 척도로 돌아온다. 이 과정은 다음 주에 예제로 다시 설명한다고 했다.

## 회고

평가 지표가 이렇게 많을 줄은 몰랐다. 정리해 보니 순위를 얼마나 신경 쓰는지에 따라 지표가 나뉜다. Hit@k는 상위 k개 안에만 있으면 되고, Precision@k와 Recall@k는 몇 개를 맞혔는지 본다. AP@k와 MRR은 얼마나 위에서 맞혔는지를 보고, NDCG는 거기에 얼마나 좋아하는지까지 더한다. 이렇게 단계적으로 보니 외울 필요 없이 이해가 됐다.

DCG 분모의 log₂(i+1)는 그냥 외우던 수식이었는데, 1/i면 너무 급하게 떨어지고 log₂(1)은 0이라서 1을 더한다는 설명을 듣고 나니 수식이 다르게 보였다.

GrowTechStack 피드도 결국 글을 순서대로 보여 주는 목록이라, 추천을 붙인다면 맞혔는지보다 위쪽에 무엇을 놓는지가 더 중요할 것이다. 지표를 고른다면 NDCG나 MRR 쪽일 것 같다. 롱테일 문제도 비슷하게 겪을 것 같다. 몇몇 큰 회사 블로그 글만 클릭을 많이 받으면, 그대로 학습한 추천은 그쪽만 계속 보여 줄 것이다.

피어슨 상관계수에서 평균은 전체 아이템으로 구하고 합은 교집합으로만 구한다는 부분은 헷갈리기 쉬워서 다음 주 예제에서 다시 확인해 보려고 한다.
