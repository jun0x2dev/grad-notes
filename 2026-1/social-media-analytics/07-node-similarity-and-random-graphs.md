# 7주차: 두 노드가 얼마나 닮았는가, 그리고 소셜 네트워크를 가짜로 만들어 보기

3장 네트워크 측정의 마지막으로 노드 유사도를 다뤘다. 이웃을 얼마나 공유하는지로 보는 구조적 동치와, 이웃끼리 닮았는지로 보는 규칙적 동치를 봤다. 이어서 4장 네트워크 모델로 넘어가, 실제 소셜 네트워크의 세 가지 특징을 정리하고 그중 가장 단순한 랜덤 그래프 두 가지(G(n, p), G(n, m))와 p를 키울 때 그래프가 어떻게 변하는지를 봤다.

## 노드 유사도

네트워크에서 두 노드가 얼마나 닮았는지를 재는 방법이다. 두 가지 관점이 있다.

### 구조적 동치

두 노드가 이웃을 얼마나 공유하는지를 본다. 형제가 부모, 형제자매를 많이 공유하는 것처럼 공통 이웃이 많을수록 비슷한 노드다.

가장 단순한 건 이웃 집합의 교집합 크기다. 하지만 이 값은 절대 크기라서 얼마나 큰지 해석하기 어렵다. 그래서 정규화한다.

```
Jaccard(vᵢ, vⱼ) = |N(vᵢ) ∩ N(vⱼ)| / |N(vᵢ) ∪ N(vⱼ)|
Cosine(vᵢ, vⱼ) = |N(vᵢ) ∩ N(vⱼ)| / √(|N(vᵢ)| · |N(vⱼ)|)
```

둘 다 0과 1 사이이고, 1에 가까울수록 공통 이웃이 많다. 예제에서 v2의 이웃이 {v1, v3, v4}, v5의 이웃이 {v3, v6}이면 교집합은 {v3} 하나이고, 코사인은 1/√(3 × 2) = 1/√6이다.

공통 이웃이 하나도 없으면 값이 0이다. 서로 직접 연결된 두 노드도 마찬가지다. 이 문제는 이웃 집합에 자기 자신을 포함해서 해결한다.

### 이 유사도가 우연보다 큰가

교집합이 크다고 해서 유의미하게 유사한 건지는 별개다. 디그리가 큰 노드끼리는 아무렇게나 연결해도 이웃이 겹칠 수 있다. 그래서 실제 공유 이웃 수에서 랜덤하게 연결했을 때의 기댓값을 뺀다.

노드 vᵢ, vⱼ의 디그리가 dᵢ, dⱼ이고 노드가 n개일 때, 이웃을 랜덤하게 골랐을 때 공유하는 이웃 수의 기댓값은 dᵢdⱼ / n이다. 실제 공유 이웃 수는 인접 행렬로 Σₖ aᵢₖ aⱼₖ다. 행 i와 행 j를 곱해 더하면, 둘 다 1인 열, 즉 둘 다 연결된 노드만 센다.

```
σ(vᵢ, vⱼ) = Σₖ aᵢₖ aⱼₖ − dᵢdⱼ / n
```

실제가 기댓값보다 클수록 닮은 것이고, 랜덤과 비슷하면 0 근처다. 정리해 보면 이 식은 aᵢ와 aⱼ 사이의 공분산이 된다. 이걸 표준편차로 나눠 정규화하면 피어슨 상관계수가 되고, 범위는 −1부터 1이다. 1에 가까울수록 유사하고 0이면 관계가 없고 −1에 가까울수록 반대다.

### 규칙적 동치

구조적 동치가 이웃을 공유하는지를 본다면, 규칙적 동치(regular equivalence)는 이웃 자체가 서로 닮았는지를 본다. 같은 사람을 알지 못하더라도, 각자 알고 있는 사람들이 서로 비슷한 역할이면 두 노드는 닮았다고 본다.

vᵢ의 이웃 vₖ와 vⱼ의 이웃 vₗ이 닮았으면 vᵢ와 vⱼ도 닮았다는 생각이다. 식으로 쓰면 재귀적이라, 인접 행렬 A의 가장 큰 고유값 λ를 구하고 α를 1/λ보다 작게 잡아서 푼다. 예제에서 6×6 행렬의 가장 큰 고유값이 2.43이라 α는 1/2.43보다 작은 0.3으로 했다. 결과로 6×6 유사도 행렬이 나오고, 값이 1에 가까울수록 규칙적으로 유사하다. 자기 자신과의 값은 의미가 없다.

## 네트워크 모델

4장의 목적부터 정리했다. 소셜 데이터를 분석하려면 실제 데이터가 필요한데, 돈을 주고 사거나 그 회사 직원이어야 해서 구하기 어렵다. 그래서 소셜 네트워크의 특징을 잘 반영하는 그래프를 인위적으로 생성해서 분석 방법을 시험해 본다. 이렇게 하면 세 가지 이점이 있다.

- 비용이 들지 않는다.
- 만드는 과정에서 어떤 특징이 어떤 성질을 낳는지 알 수 있어 실제 네트워크를 더 잘 이해할 수 있다.
- 특정 특징을 조절하면서 결과가 어떻게 달라지는지 볼 수 있다. 실제 네트워크로는 못 하는 실험이다.

생성한 그래프가 실제 소셜 네트워크의 특징을 반영하지 않으면 분석해도 의미가 없다. 그래서 먼저 실제 소셜 네트워크의 특징을 알아야 한다.

## 실제 소셜 네트워크의 세 가지 특징

### 1. 디그리가 멱법칙을 따른다

대부분의 사용자는 팔로워가 적고 극소수의 인플루언서만 수십만에서 수백만 명을 가진다. 디그리 분포가 한쪽으로 크게 치우쳐 있다. 디그리가 d인 노드의 비율은 다음과 같다.

```
P(d) = a · d^(−b),   b는 대개 2~3 사이
```

양변에 로그를 취하면 ln P(d) = −b ln d + ln a라는 직선이 된다. 그래서 로그-로그 그래프에서 직선으로 보이면 멱법칙을 따른다고 본다. 블로그, 트위터 등을 이렇게 그려 보면 대체로 직선에 가깝게 나온다. 다만 이게 멱법칙임을 보장하는 건 아니고 대체로 그렇다는 정도다.

멱법칙은 소셜 미디어에 한정되지 않는다. 수업에서 든 예는 이렇다.

- 하루에 k통의 전화를 받는 사람의 비율은 1/k²에 비례한다. 하루에 두 통을 받는 사람은 전체의 1/4, 열 통은 1/100, 백 통은 1/10,000 정도다.
- 책 판매, 논문 인용, 트위터 팔로워 수도 같은 모양이다.
- 부의 분배, 도시 인구, 웹사이트 방문자도 마찬가지다. 서울에 몰려 있는 한국 인구, 해안에 몰려 있는 미국 인구가 그렇다.

멱법칙의 꼬리는 길다(long tail). 아마존의 경우 인기 상품의 매출 비율이 43%이고, 인기가 없지만 종류가 매우 많은 상품들의 매출을 합치면 57%였다는 예를 들었다.

### 2. 군집 계수가 높다

내 친구의 친구가 내 친구일 확률이 높다. 지난 시간에 본 지역 군집 계수가 소셜 네트워크에서 크게 나온다. 예를 들어 페이스북에서는 A-B, B-C가 친구이면 A-C도 친구인 경우가 50% 정도라고 했다.

### 3. 평균 경로 길이가 짧다

임의의 두 사람을 연결하는 최단 경로가 짧다. 흔히 말하는 6단계 분리다.

- 밀그램의 실험: 네브라스카 196명과 보스턴 100명, 총 296명에게 편지를 주고 자기가 아는 사람에게 전달하게 해서 목표 인물에게 닿게 했다. 296명 중 64명이 도달했고, 거쳐 간 사람 수는 6명이 가장 많았다.
- 에르되시 수: 수학자 에르되시와 공저 관계로 연결되는 단계 수다. 에르되시는 1,500편 이상의 논문을 냈고, 평균은 4.65, 최댓값은 13이라고 했다.

실제 네트워크들에서 평균 경로 길이를 보면 전반적으로 작게 나온다.

### 세 가지를 동시에

세 가지 특징을 모두 만족하는 모델은 아직 없다고 했다. 이어지는 모델들(랜덤 그래프, 스몰 월드 모델, 선호적 연결 모델)은 각각 일부만 반영한다. 그래서 어느 특징이 중요한지 정해서, 그 특징을 잘 반영하는 모델로 그래프를 생성해 시험한다.

## 랜덤 그래프

친구 관계가 랜덤하게 생긴다고 가정하고, 규칙 없이 랜덤하게 노드를 연결하는 모델이다. 두 가지가 있다.

### G(n, p)

노드 n개에서 가능한 모든 쌍을 확률 p로 독립적으로 연결한다. 가능한 엣지의 총수는 C(n, 2) = n(n−1)/2다. p = 1이면 모든 쌍이 연결된 완전 그래프이고, p가 0에 가까우면 엣지가 거의 없는 성긴 그래프다. 엣지 수의 기댓값은 C(n, 2) · p이고, 정확히 몇 개가 나올지는 보장되지 않는다. 극단적으로는 엣지가 하나도 없거나 완전 그래프가 나올 수도 있다.

한 노드의 평균 디그리 c는 (n − 1)p다. 그래서 원하는 평균 디그리 c와 노드 수 n이 주어지면 p = c / (n − 1)로 정한다. 평균 디그리를 5로 하고 싶으면 p를 거기에 맞춰 정한다.

특정 노드가 정확히 k개의 엣지를 가질 확률은 이항 분포를 따른다.

### G(n, m)

노드 n개에 엣지를 정확히 m개로 만든다. 가능한 엣지 C(n, 2)개 중 m개를 뽑는 모든 경우가 같은 확률이다. n이 아주 크면 m을 C(n, 2) · p로 맞출 때 G(n, p)와 G(n, m)은 비슷한 그래프가 만들어진다. 차이는 엣지 개수가 보장되는지다. G(n, m)은 보장하고 G(n, p)는 평균적으로만 그렇다.

## p를 키우면 그래프가 어떻게 변하는가

p를 올리면 노드들이 서로 연결되기 시작하고, 연결된 서브그래프(연결 컴포넌트)가 생긴다. 그중 가장 큰 것이 자이언트 컴포넌트(giant component)다. 노드 10개로 p를 바꿔 가며 평균 디그리 c, 지름, 자이언트 컴포넌트 크기를 표로 봤다.

- p가 아주 작으면 엣지가 거의 없고 자이언트 컴포넌트가 없다.
- c가 1이 되는 지점에서 자이언트 컴포넌트가 나타난다. c가 1보다 작을 때는 작은 조각들뿐이고, 1이 되면 갑자기 많은 노드가 하나의 컴포넌트로 합쳐지기 시작한다.
- 지름은 c = 1 부근에서 최대가 되고, p를 더 올리면 엣지가 많아져 계속 줄어든다. p가 1이면 모든 쌍이 직접 연결되어 지름이 1이다.
- 자이언트 컴포넌트에 속한 노드 수는 p가 늘수록 증가해 전체 노드로 수렴한다.

그래프 전체가 연결되려면 디그리가 0인 노드가 없어야 한다. n이 아주 클 때 이 조건을 계산하면 c ≥ ln n이어야 한다. p = c / (n − 1)이니 연결된 그래프를 얻기 위한 p의 최솟값은 ln n / (n − 1) 정도다. p가 이보다 작으면 일부 노드가 고립된 채로 나올 수 있다.

## 회고

구조적 동치를 처음에는 이웃 집합의 교집합을 세는 것이라고만 이해했는데, 우연히 겹칠 기댓값을 빼야 한다는 부분에서 한 번 더 생각하게 됐다. 디그리가 큰 두 노드는 연결을 아무렇게나 해도 이웃이 많이 겹친다. 그 겹침까지 유사하다고 쳐 버리면 허브끼리는 항상 닮은 것으로 나온다. 기댓값을 빼면 그 효과가 사라진다. 추천 시스템에서 인기 아이템끼리는 항상 유사도가 높게 나오던 문제와 같은 구조다.

데이터를 구하기 어려워서 가짜 그래프를 만든다는 4장의 동기는 이해가 잘 됐다. 서비스를 개발할 때 부하 테스트용 더미 데이터를 만드는 것과 같은 고민이다. 무작위로 만든 데이터가 실제 데이터의 분포를 따르지 않으면 테스트 결과가 실제를 대변하지 못한다.

디그리가 멱법칙을 따른다는 건, 이 분포에서 평균 디그리를 보면 오해를 부른다는 뜻이다. 대부분은 평균보다 훨씬 작고 소수가 크게 끌어올린다. 서비스 지표를 평균으로만 보지 않고 분포를 같이 봐야겠다.

c = 1에서 자이언트 컴포넌트가 갑자기 생긴다는 건 인상적이었다. 연결이 조금씩 늘어나는 동안 별일 없다가 어느 지점에서 한꺼번에 하나로 합쳐진다. 서비스에서 어느 순간 사용자가 서로 연결되기 시작하면 네트워크 효과가 터지는 것이 이런 모양일 것 같다.
